# 전체 기능 점검 절차 (QA 체크리스트)

기능이 추가될 때마다 이 문서의 해당 절을 갱신하고, 릴리스 전이나 큰 변경 뒤에는 1~7절을 순서대로 다시 수행한다. 각 항목은 `[ ]`에 결과를 적어 가며 쓴다.

## 0. 준비

| 항목 | 내용 |
|---|---|
| 실행 | `.\dev.ps1` (로그: `.dev-logs\backend.log`, `.dev-logs\frontend.log`) |
| 브라우저 | 일반 창 1개 + 시크릿 창 2개(사용자별 세션 분리). 개발자도구 Network·Console 탭을 열어 둠 |
| 테스트 파일 | (a) 정상 CSV(한글, 5행 내외) (b) 정상 XLSX (c) EUC-KR(MS949) CSV (d) 1,000행 이상 XLSX 또는 CSV (e) 헤더 중복 파일 (f) 빈 파일 (g) 확장자만 xlsx인 깨진 파일 (h) 따옴표 안에 줄바꿈이 있는 CSV |
| 테스트 계정 | 관리자(초기 시드), 김일반(프로젝트 A 참여, 소유자 역할), 박참여(프로젝트 A 참여), 이외부(미참여) |
| 원칙 | 기존 운영 데이터셋은 수정·삭제하지 않고 새로 만든 테스트 데이터로만 확인 |

## 1. 자동 점검 (코드 변경 직후)

- [ ] 백엔드 단위 테스트: `./gradlew test --tests 'com.dgjs.backend.service.*' --tests 'com.dgjs.backend.config.*' --tests 'com.dgjs.backend.domain.*'` 통과 (`JAVA_HOME`은 JDK 17)
- [ ] 프론트 `npm run lint` 오류 0
- [ ] 프론트 `npm run build` 성공
- 참고: `contextLoads`는 MySQL이 필요해 별도 확인

## 2. 서버 기동과 DB

- [ ] backend.log에 `Started BackendApplication`, `Validation failed for query`·`Could not create query`·외래키 경고 없음
- [ ] 사원이 비어 있었다면 초기 관리자 임시 비밀번호가 WARN 로그에 한 번 출력됨
- [ ] 기존 데이터셋 소유자 이관 로그 출력, 재시작해도 같은 결과(멱등)
- [ ] `SELECT dataset_id, owner_id, project_code FROM dataset_meta;` 에서 owner_id가 `E0001` 형식
- [ ] 테이블 존재: `department`, `project`, `employee`, `project_member`, `dataset_meta`, `dataset_column`, `dataset_row`
- [ ] http://localhost:8080/swagger-ui.html 열림

## 3. 인증과 세션 (모듈 A-2)

- [ ] 비로그인으로 `/data` 접근 시 `/login`으로 이동
- [ ] 틀린 비밀번호와 없는 이메일이 같은 문구("이메일 또는 비밀번호가 올바르지 않습니다.")
- [ ] 임시 비밀번호 상태 로그인 시 `/me`로 이동하고 다른 메뉴 이동이 막힘
- [ ] 비밀번호 변경: 8자 미만, 숫자 없음, 영문 없음, 64자 초과 거부 / 정상값 성공 후 목록 이동
- [ ] 현재 비밀번호가 틀리면 변경 거부
- [ ] 로그아웃 후 뒤로가기로 보호 화면에 들어가지 못함
- [ ] 세션 만료(유휴 30분)는 쿠키 만료 시각으로 확인하거나, 로그인 후 쿠키 삭제 → 다음 동작에서 `/login`으로 이동
- [ ] 같은 이메일 5회 연속 실패 후 6번째에 429 문구(백엔드 재시작으로 초기화)
- [ ] CSRF: 개발자도구에서 `X-XSRF-TOKEN` 헤더 없이 변경 요청을 보내면 403
- [ ] 비활성(INACTIVE) 처리된 사원이 로그인하면 일반 실패 문구, 이미 로그인한 상태면 다음 동작에서 로그인 화면으로 이동

## 4. 기준 정보와 관리 (모듈 A-1, 화면은 A-4 전까지 Swagger)

관리자 세션에서 수행. 일반 사용자 세션으로 쓰기·사원 API를 호출하면 403인지 함께 확인.

- [ ] 부서: 생성(`D001` 형식), 이름 중복 거부, 수정, 소속 사원이 있으면 삭제 거부(400), 없으면 삭제
- [ ] 프로젝트: 생성(`P001`), 이름 중복 거부, 수정, 삭제 시 참여자 연결 삭제 + 연결 데이터셋이 미지정으로 변경
- [ ] 참여자: 추가, 중복 추가 거부, 비활성 사원 추가 거부, 제거
- [ ] 사원: 발급 응답에 `tempPassword`가 한 번만 포함, 이메일 소문자화·중복 거부, 직급·역할 enum 외 값 거부
- [ ] 사원 목록: 페이징, 이름·이메일 검색, 부서 필터
- [ ] 비밀번호 초기화 후 새 임시 비밀번호로 로그인 → `/me` 강제 이동
- [ ] 마지막 활성 관리자의 역할 변경·비활성화 거부
- [ ] `GET /api/projects/mine`: 일반 사용자는 참여 프로젝트만, 관리자는 전체

## 5. 데이터셋 적재 (모듈 B)

### 5-1. 미리보기와 스키마 확정 (`/upload`)
- [ ] 정상 CSV/XLSX: 헤더, 샘플 10행, 타입 추정(전부 숫자면 NUMBER, 아니면 STRING)
- [ ] MS949 CSV와 BOM 포함 UTF-8 CSV의 한글이 깨지지 않음
- [ ] 따옴표 안 줄바꿈·`""` 이스케이프 CSV가 한 셀로 읽힘
- [ ] 빈 헤더, 빈 파일, 깨진 파일은 구조 오류 문구 표시
- [ ] 중복 컬럼명은 1단계에서 수정 가능하고, 수정 전에는 다음 단계 진행이 막힘
- [ ] 컬럼 타입(STRING/NUMBER/DATE/BOOLEAN) 변경 가능
- [ ] 데이터셋 이름 필수, 프로젝트 선택지는 내 프로젝트(관리자는 전체), 비우면 미지정

### 5-2. 비동기 적재
- [ ] 적재 시작 후 진행률이 1초 단위로 갱신되고 완료 시 상세로 이동
- [ ] 1,000행 이상 파일이 끝까지 적재되고 행 수가 일치
- [ ] 적재 중 목록에 PROCESSING 데이터셋이 보이지 않음
- [ ] 적재 중 다른 화면으로 이동했다 돌아와도 서버 처리는 계속되고 목록에 결과가 나타남
- [ ] 실패 유도(적재 중 서버 종료 등) 시 불완전 데이터셋이 목록에 남지 않음 (실패 시 DB 정리 확인)
- [ ] 소유자가 로그인 사용자로 기록됨 (DB `owner_id`)

### 5-3. 수동 스키마 생성
- [ ] 컬럼명·타입을 직접 정의해 빈 데이터셋 생성, 상세에서 행 0개
- [ ] 컬럼명 빈 값·중복 거부
- [ ] 소유자와 프로젝트가 올바르게 기록됨

## 6. 조회·편집 (모듈 C)

### 6-1. 목록 (`/data`)
- [ ] 이름, 프로젝트(없으면 미지정), 소유자(이름), 행·열 수, 등록일, 최근 적재일 표시
- [ ] 정렬, 페이징 동작
- [ ] 삭제 버튼은 삭제 권한이 있을 때만 표시, 삭제 전 확인 모달

### 6-2. 상세 (`/data/:id`)
- [ ] 정보 탭: ID, 분류, 행·열 수, 등록일, 최근 적재일, 소유자(이름·사번), 프로젝트
- [ ] 데이터 탭: 서버사이드 페이징(전체 행을 한 번에 받지 않음, Network에서 `rows?page&size` 확인), 페이지 크기 변경
- [ ] 큰 데이터셋에서 마지막 페이지 이동이 빠르고 정확함

### 6-3. 행 추가·수정·삭제 (타입별 검증)
| 타입 | 통과해야 하는 값 | 거부되어야 하는 값 |
|---|---|---|
| STRING | 문자, 숫자, true | 객체·배열(Swagger로 확인) |
| NUMBER | `12`, `3.5`, `"7"` | `"1,000"`, `abc` |
| DATE | `2026-10-31`, `2026-10-31T09:30`, `2026-10-31 09:30` | `2026/10/31`, `31-10-2026` |
| BOOLEAN | true, false, `"TRUE"` | `yes`, `1` |

- [ ] 빈 값은 모든 타입에서 저장됨(빈 문자열)
- [ ] 스키마에 없는 키는 거부
- [ ] 수정 시 기존 값과 같은 컬럼은 재검증하지 않음(과거 데이터의 형식 불일치 값이 있어도 다른 컬럼 수정 가능)
- [ ] 행 삭제 후 목록·행 수 반영
- [ ] 행 추가·수정 후 최근 적재일 갱신

### 6-4. 메타 수정
- [ ] 이름·설명·분류 수정 저장, 이름 비우기 거부
- [ ] 프로젝트 변경, 비움 → 미지정 반영
- [ ] 소유자·관리자가 아닌 편집자는 프로젝트 칸 비활성 + 안내 문구
- [ ] 저장 직후 상세에 최신 값 표시

## 7. 권한 매트릭스 (모듈 A-3)

대상 데이터셋: 김일반 소유, 프로젝트 A 연결. 화면 표시와 API 직접 호출(403) 둘 다 확인.

| 사용자 | 조회 | 메타 수정 | 행 추가·수정·삭제 | 데이터셋 삭제 | 프로젝트 연결 변경 |
|---|---|---|---|---|---|
| 관리자 | 가능 | 가능 | 가능 | 가능 | 가능 |
| 김일반(소유자, 참여자) | 가능 | 가능 | 가능 | 가능 | 가능(참여 프로젝트로만) |
| 박참여(참여자) | 가능 | 가능 | 가능 | 불가(버튼 없음, API 403) | 불가(칸 비활성, API 403) |
| 이외부(미참여) | 가능 | 불가 | 불가 | 불가 | 불가 |

- [ ] 위 표 전체가 화면과 API에서 일치
- [ ] 프로젝트 미지정 데이터셋: 소유자·관리자만 수정 가능, 박참여는 버튼 없음·API 403
- [ ] 미참여 프로젝트로 연결 변경 시도 시 403
- [ ] 프로젝트 연결을 해제하면 박참여가 즉시 수정 권한을 잃음
- [ ] 일반 사용자의 `GET /api/employees` 403
- [ ] 권한 판정이 요청마다 갱신됨: 관리자가 참여자를 제거한 직후 박참여의 수정 시도가 403

## 8. 공통 오류와 화면 품질

- [ ] 존재하지 않는 데이터셋 ID 접근 시 404 안내
- [ ] 잘못된 JSON·필수 값 누락은 400 + 한국어 `message`
- [ ] 500 응답에 내부 정보(스택, SQL)가 노출되지 않음
- [ ] 화면 오류는 `message.error`로 표시되고 빈 화면·무한 로딩이 없음
- [ ] 사이드바 열기·닫기, 상단바, 좁은 창 폭에서 레이아웃이 깨지지 않음
- [ ] 브라우저 Console에 에러·경고(antd deprecated 포함) 없음
